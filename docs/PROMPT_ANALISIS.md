AFIRMACIONES DE LA MONOGRAFÍA DE JULIÁN A VERIFICAR CONTRA EL CÓDIGO (fase 10)
- Backend hexagonal con capas aplicación (input = puertos de entrada de casos de uso; output = gateways/puertos de salida), dominio (casosUso, helper con constantes y objeto de respuesta paginada, modelos) e infraestructura (configuración, input con controladores + DTO petición + DTO respuesta + mapeador, output con encoder, exportador .docx, formateador de excepciones, JWT, manejador de excepciones, persistencia con entidades, gateway, mapeador propio y repositorios).
- Mapeador propio (interfaz de contrato + implementaciones explícitas) que sustituyó a ModelMapper para evitar ciclos y cargas innecesarias; ModelMapper solo en conversiones simples.
- Eliminaron @OneToMany/@ManyToOne redundantes para evitar ciclos de carga.
- JWT con vigencia de 5 horas, firmado con secreto, con los roles dentro del token; filtro JwtFiltroAutenticacion; respuesta de error cuando no hay permiso; usuarios deshabilitables.
- Patrones citados: Controller, Repository (UsuarioRepositorio extiende JpaRepository con consultas propias), Inyección de Dependencias por constructor, Facade (gateway de Logs), DTO (por ejemplo RespuestaDTORespuesta), Singleton vía @Service (TipoSolicitudExcelService).
- SOLID citado: SRP (JwtFiltroAutenticacion), OCP (ProcesadorArchivos<T>), LSP (UsuarioLiviano, Usuario, Funcionario), ISP (ExcepcionesFormateadorIntPuerto), DIP (casos de uso dependen de interfaces *IntPuerto como TipoSolicitudGatewayIntPuerto, UsuarioGatewayIntPuerto, LogCUIntPuerto, RolGatewayIntPuerto).
- Base de datos MySQL, Hibernate vía Spring Data JPA; entidades: usuarios, roles, solicitudes, tipos de solicitud, orden del día, respuestas, consecutivos, logs.
- Errores de negocio como HTTP 500 con JSON {codigoError, mensaje, httpCodigo, url, metodo}; ruta base /api/unicauca/fiet/consejo.
- Carga masiva de usuarios y tipos de solicitud por Excel; exportación del Orden del Día en .docx; subida de anexos (PDF) con validación de formato.
- Frontend Angular con carpetas core (componentes por perfil/módulo, páginas, modelos, servicios), layouts, shared (componentes reutilizables), environments; componentes genéricos y reutilizables (por ejemplo app-page-component como esqueleto de vistas); PrimeNG.
- Pruebas: según la monografía solo Postman (unitarias, integración, carga y estrés) y UAT; verificar si hay tests automatizados reales (JUnit, Mockito, Karma/Jasmine, Jest) y cuántos.
- Docker: Dockerfile backend (Java 17, puerto 8080, ruta de uploads, jar ya compilado), Dockerfile frontend multi-stage (Node alpine, puerto 4200), docker-compose con backend + MySQL con healthcheck, volumen para archivos, depends_on, límites de memoria y reinicio.
- Ramas Git Prod y Dev; feature/..., hotfix/....
